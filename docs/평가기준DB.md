# 파이프라인: 평가기준DB

어디가 **대학정보 > 평가기준 및 입시결과 > 전형별 주요사항**(Ⅱ.종합·Ⅲ.교과·Ⅳ.수능)을
대학×전형유형×섹션 단위로 쪼개 **SQLite**에 적재한다. (Ⅰ.공통 탭은 제외)

구글시트(`01_fact_admissions`)에는 **넣지 않는다** — 시트는 `지표+척도+값` 수치 롱포맷이고
평가기준은 서술·표라서 기존 입력 규칙에 맞지 않는다(신규 지표 금지 원칙).

## 1) 크롤 (브라우저 JS, 로그인 불필요)

`GET /ucp/uvt/uni/univDetailSelection.do?menuId=PCUVTINF2000&unvCd=<코드>&searchSyr=2027`
**한 번**이면 3개 탭 내용이 전부 들어 있다(서버 렌더, XHR 아님 — 입시결과 아코디언만 XHR).

- 추출: `.accordionBtn` 중 텍스트에 `주요사항` 포함 → 바로 다음 `.accordionCon` 3개(종합·교과·수능 순).
- 내용은 대학이 직접 쓴 리치텍스트(raon 에디터). **블록 단위로 훑어야** 한다
  (텍스트 노드 단위로 쪼개면 `[`, `전형별 특성`, `]` 이 따로 나와 섹션 인식 실패).
  - 자식 원소 순회 → `TABLE`이면 표, 표를 품고 있으면 재귀, 아니면 `innerText` 한 조각.
  - **셀 안에 중첩 표**가 흔함 → 중첩 표는 셀 안의 `td,th`를 공백으로 이어붙인다
    (안 하면 `100 120 80`이 `10012080`으로 붙어버림).
  - 버릴 것: `A`(아코디언 표식), `keditor_body` CSS 덩어리.
- 섹션: 한 줄이 통째로 `[제목]`/`【제목】`인 조각이 구분자. 그 아래 조각들이 그 섹션 소속.
- 16개 대학 결과를 배열로 모아 **1회 다운로드**(다중 다운로드 차단 회피) → `adiga_평가기준_2027.json`.

## 2) 적재 (파이썬, stdlib sqlite3)

```
py adiga_criteria_db.py <크롤.json> [db경로]   # 적재 + 검산 + 커버리지 요약
py adiga_criteria_db.py --검색 "면접"           # 내용 LIKE 검색
py adiga_criteria_db.py --selfcheck
```
- 테이블 `criteria(대학명, unvCd, 학년도, 전형유형, 섹션, 순번, 종류, 내용)`.
  `종류`=`text`|`table`, 표는 TSV 문자열.
- **순번은 적재기가 탭 단위로 다시 매긴다** — 한 탭에 같은 섹션명이 두 번 나오는 대학이 있어
  섹션별로 매기면 PK가 충돌한다(서울대 수능 `[전형요소 및 배점]` 3회).
- 검산: JSON 행수 = DB 행수 = 대학별 소계 합.

## 정규화 수준(확인된 한계)

| 수준 | 가능? | 근거 |
|---|---|---|
| 섹션 분해 | **가능** | 16개 대학 중 `전형별 특성`·`전형별 전형요소` 16/16, `서류평가`·`면접평가` 15/16 |
| 표를 표로 보관 | 가능 | 281개 표를 TSV로 |
| 표를 컬럼으로 정규화 | **불가(규칙 기반)** | 헤더·표 순서가 대학마다 다름(서울대 `구분/전형개요/비고` vs 연세대 `구분/전형방법/비고`), 다단 병합 헤더 |
| 서술형(평가요소 정의 등) | 불가 | 자유 서술 — 문서로 두고 검색 |

→ 반영비율·수능최저 같은 **정형 필드가 필요하면 규칙 파싱 말고 LLM 추출**로 가고,
   추출값은 원문 조각(`섹션`+`순번`)을 근거로 함께 저장해 검증 가능하게 둔다.
